# Diagnostics 组件说明

## 模块功能

`DiagnosticsPanel` 提供数据健康诊断入口, 用于集中展示 Tushare、AI、关键缓存、同步动作和数据库迁移状态。
FR-197 起, 诊断页定位为今日看板主工作台的恢复工具, 帮助用户在暂无信号、数据源缺失或初始化失败时判断是系统异常、数据未就绪, 还是当前规则暂未发现机会。

## 实现思路

组件通过 `window.api.diagnostics.getHealth()` 获取主进程生成的诊断快照, 按配置状态、数据新鲜度、同步任务和数据库状态分组展示。可自动处理的诊断项通过 `window.api.diagnostics.runCheck()` 触发现有同步或补种逻辑, 不绕过后端权限校验。

FR-195 起, 诊断页可接收 App 层的一键初始化任务状态, 展示任务是否正在执行、完成数量和最近消息。诊断页本身不编排队列, 只提供查看和启动入口。
FR-196 起, 诊断页新增数据安全卡片, 展示数据库路径、大小、备份目录、最近备份、备份数量和迁移版本, 并提供立即备份、打开备份目录和导出关键数据入口。
FR-214 起, 诊断页新增全市场历史日线同步入口, 通过 `diagnostics:runCheck('syncHistoricalDaily')` 将近 2 年全市场日线写入 `daily_close_cache`, 并可接收 `diagnostics:historicalDailyProgress` 进度事件。
FR-215 起, 数据安全卡片新增全市场基座包导出/导入入口, 用于把 `daily_close_cache`、`stock_basic_cache` 和 `trade_cal` 以 `.twbase.sqlite` 单文件分享给其他用户。
FR-229 第173阶段起, 诊断快照增加历史日线质量摘要, 展示480日同步目标、520日保留窗口、实际覆盖、事实日期范围、关键字段缺失率及最近一次清理结果。该摘要复用现有诊断通道, 不改变初始化依赖的 `freshness.dailyClose` 语义。
FR-246 第一批起, 顶部新增关键数据质量区域, 自动检查股票基础、交易日历、日线/复权、竞价、核心基准和产业财务。普通刷新只读本地SQLite；只有“运行完整检查”或用户显式补齐动作保存正式快照或联网。
FR-248 第一批起, 关键数据质量区域之后新增 `AIQualityEvaluation`。该工作台通过 `window.api.aiEvaluation` 读取版本化合成评测集、已配置厂商、后台运行和历史结果；一次显式运行固定调用四个样本, 不跨厂商降级。页面优先展示明确终态、综合分、五维得分和同身份历史差值, 失败规则与模型原文按需展开, 不提供逐条人工放行入口, 也不把合成样本写入新闻、会话或决策信号。

## 主要 props/state/事件流

- `onNavigateConfig`: 当用户点击“打开数据源配置”或“打开 AI 配置”时, 通知配置抽屉切换到对应页签。
- `onOpenGuide`: 当用户点击“打开新用户引导”时, 通知 App 显示冷启动引导面板。
- `initializationFlow`: 当前会话中的一键初始化任务状态。
- `onStartInitialization`: 从诊断页启动完整初始化任务流。
- `snapshot`: 当前诊断快照。
- `snapshot.dailyCloseQuality`: 历史日线覆盖、字段完整性和跨重启清理状态。
- `snapshot.dataQuality`: 六类关键数据集的可信状态、事实范围、影响模块、质量说明和主要恢复动作。
- `AIQualityEvaluation`: 独立加载并轮询AI评测运行；配置页切换不会取消主进程任务, 重新进入后按运行ID恢复进度和终态。
- `loading`: 重新检查中的加载状态。
- `runningAction`: 当前执行中的诊断动作, 用于禁用重复点击。
- `syncHistoricalDaily`: 长任务型诊断动作, 用于补齐全市场历史日线底座。
- `dataSafety`: 数据安全状态快照, 来自 `window.api.dataSafety.getStatus()`。
- `dataSafetyAction`: 当前执行中的备份、打开目录或导出动作。
- `basePreview`: 当前选择的基座包预览信息, 展示 manifest 后等待用户确认导入。
- `error/actionMessage`: 展示诊断动作失败或成功反馈。

## 特殊逻辑备忘

- 页面不展示完整 Token、API Key 或 Base URL 中的敏感凭据。
- AI评测只展示模型名称和汇总Token用量, 不读取或展示API Key、Base URL；历史差值只在评测集版本、厂商、模型和业务提示词指纹可比较时出现。
- 数据质量主层不展示表名、内部ID或原因代码；技术原因仅以本地化说明按需展开。
- 产业财务没有登记公司时按“当前无待检查公司”处理，不把不适用伪装成全局异常。
- 诊断动作只复用主进程已有同步函数, 失败时以可读错误返回, 不让 UI 崩溃。
- 全市场历史日线同步只依赖 Tushare `daily`/`daily_basic` 和本地 `daily_close_cache`, 不补全分钟线、不调用 AI。
- 日线字段缺失率由主进程一次聚合查询计算, 空表返回未知状态, 不显示为0%缺失。
- 日线字段缺失、异常行情和未来事实由同一次聚合返回；旧日线质量区与关键数据质量区共享结果，避免在大库上重复全表扫描。
- 显式交易日历同步区分成功、空响应和请求失败；后两者保留本地已有数据并显示可读错误，不误报完成。
- 最近清理状态来自单行持久化记录, 应用重启后仍可查看成功、失败和删除行数; 失败摘要不包含数据库路径或堆栈。
- 基座包导出采用白名单表, 不包含 Token、API Key、持仓、预测记录、今日看板处置、AI 会话或用户设置; 导入只 merge 基础表, 不覆盖个人数据。
- 诊断页是冷启动引导的可恢复入口, 但不自己持久化引导状态。
- FR-194 起, 诊断快照也作为初始化闭环和今日看板空态的输入来源; 诊断页仍只负责展示与动作入口。
- FR-195 的任务状态不持久化到数据库, 应用重启后以新的诊断快照重新派生。
- FR-196 的恢复能力首版只打开备份目录并展示说明, 不自动覆盖当前数据库, 避免误操作损坏用户数据。
- 导出配置摘要时只展示 provider、模型名、是否已配置密钥等非敏感信息, 不导出完整 Token、API Key 或 Base URL。
