# 短线策略组件

## 模块功能

短线策略模块承载早盘集合竞价、尾盘 30 分钟、涨停板监控、连板龙头、首阴回踩、低吸雷达、策略实验室、筹码结构和策略评估等子页签。FR-225 起, 个性选股和条件积木的主入口收敛到策略实验室。

FR-225k 起, 策略实验室首批完整交付分钟规则自由组合：用户可配置股票池、分钟条件阈值、`AND / OR / NOT` 嵌套组、严格/评分模式、权重和硬门槛，保存的规则快照直接参与真实筛选。命中证据逐条件展示配置值与实际值，宽屏固定在右侧、窄屏通过证据抽屉查看；停用条件不参与得分，缺数据不被当作反证。通用日线 DSL 与真正两阶段组合仍留给后续批次。

FR-242 起, “策略评估”默认按真实信号事件横向比较早盘竞价和策略实验室的次日、第2/3/5个交易日表现，展示双等权收益、胜率、分位数、超额、覆盖和重合关系。原资金参数回测保留为“历史报告”，不要求用户为日常策略比较配置模拟账户。

FR-250 第一批起, “涨停板监控”升级为涨停质量决策工作台。主进程按首次封板时间、开板次数、封单金额、题材涨停广度和当前连板位置形成透明五维质量分层；字段缺失保持未知，龙虎榜卖压与三次以上开板执行硬降级。实时连板位置只承接交易日历确认的上一交易日连续涨停，不读取历史最高板数。页面先展示全池结论与题材聚合，再按重点观察、选择性观察和封板脆弱排序候选，右侧固定展示证据、风险、继续确认和明确失效条件；单击选择、双击或显式按钮打开公共日K与筹码抽屉。旧竞价回测弹层被移除，“历史表现”定向进入策略评估的历史报告并选中 `shortTerm.limitBoardMonitor`。同策略同事实日信号原子替换，刷新不产生重复记录。

FR-250 第二批起, “连板龙头”升级为连板梯队与题材竞争工作台。盘后按真实连板高度、首次封板、开板次数、封单、连续两日换手和同题材连板梯队形成五维研判；盘中 `rt_k` 缺少的连板高度、开板和换手保持未知，不再使用 `2.0`、`0`、`2板`或“缩量硬板”默认值。题材涨停广度只进入一次梯队维度，高标必须拥有同题材梯队证据才能成为核心候选。页面展示最高板、高度层、成形题材、题材竞争、候选证据/风险/确认/失效，并以 `shortTerm.secondBoardLeader` 幂等保存核心和有限竞争信号；历史表现进入统一策略评估历史报告。

FR-250 第三批起, “尾盘30分钟”升级为尾盘行为与次日风险研判工作台。主进程以精确14:30价格、收盘位置、分钟成交参与、路径最大回撤/方向效率和开盘价/昨收得失形成五维结论；缺少精确14:30或成交量时保持未知，不再使用固定形态分数、伪均线或任意最早分钟兜底。旧六形态仅作为可同时命中的路径事实标签。页面展示市场结论、主动/确认/撤退/不足候选、选中证据、风险和次日确认/失效条件；`shortTerm.closingHalfHour` 只保存主动和有限确认候选，15:01自动定稿并可在非交易日或重启后恢复最近事实日，历史表现进入统一策略评估历史报告。

FR-250 第四批起, “首阴回踩”升级为近期高标事件状态机。候选只从最近交易窗口内真实三板及以上连板事件向后追踪，首次断板为首次分歧，其后三个交易日内等待收盘站上分歧日高点确认；收盘跌破分歧日低点或窗口超时即失败。盘中越过/跌破边界只提示，不冒充收盘事实。旧全历史最高板扫描、缺失换手写0%、固定40%安全阀、伪尾盘缩量和伪次日弱转强已删除。页面展示状态分布、确认/失效线、修复进度、换手比较、题材支撑及选中研判；`shortTerm.firstYinDip` 只保存确认和有限等待候选，历史表现进入统一策略评估历史报告。

FR-250 第五批起, “低吸雷达”不再把趋势、套利和轮动候选混入同一强度表。趋势模式只观察近30个交易日真实二板及以上、MA10/20/30完整、位于均线上下2%、未破MA30且MA20不向下的回踩；套利模式要求涨停少于30、主流题材广度下降过半、个股处于0%至-5%受控回撤，并有真实资金净流入或盘后缩量确认；轮动模式要求前一日五板以上龙头打开涨停但仍红盘，候选与其同题材、近期最高不超过二板且涨幅低于龙头一半。未知事实保持“待补”，历史请求不混入今日 `rt_k`。三个模式分别以 `shortTerm.dipBuy.trend`、`shortTerm.dipBuy.arbitrage`、`shortTerm.dipBuy.rotation` 保存和评估合格信号；环境阻断、失败、不足和回退快照不进入收益样本。页面按模式展示环境门槛、关键事实、具体关联龙头、风险、确认/失效、公共股票抽屉及统一历史入口。

FR-250 第244阶段起, 五个决策工作台页头的刷新、历史表现和题材数据统一使用 `SHORT_TERM_WORKBENCH_ACTION_CLASS`，保持44px高度、同一边框/表面/字重及完整交互状态。`ConceptDataToolsButton` 按上下文提供 `compact/workbench` 变体：早盘集合竞价保留32px紧凑工具条，决策工作台使用44px工作台样式；同一操作组内部不得混用两种变体。

## 实现思路

根组件负责子页签切换与数据源状态提示，各子组件通过 preload 暴露的 IPC 命名空间读取快照、触发同步或接收进度事件。筹码结构页继续复用原 `chipMonitor` 子页签键和监控股池, 通过独立的 `chipStructure` IPC 读取结构摘要与单股详情。持仓股通过独立的 `portfolio` 来源导入，不与股票走势图自选列表混用。

FR-228 P1 起, `ChipMonitor` 升级为筹码结构事实工作台。页面采用“左侧高密股票队列 + 右侧固定事实详情”布局, 展示成本分位、获利/套牢结构、价格级筹码峰、集中度、现价成本偏离、1/3/5/12 个有效筹码交易日变化、双源一致性和数据缺口。页面只描述可验证的成本分布事实, 不根据成本区间推断散户、主力或机构身份。列表、筛选、模式切换和详情查询只读取本地缓存; 只有用户点击“同步结构”或确认导入后才调用 `chipStructure:refresh` 访问 Tushare。`cyq_perf` 与 `cyq_chips` 独立保存, 任一来源成功即可形成 `partial`, 空响应不会覆盖已有有效快照, 不同交易日的数据不会拼接为同一结论。

FR-228 P2 起, 单股详情新增独立机构席位行为证据区, 只展示 `top_inst` 的公开席位名称、买入额、卖出额、净额、占成交额比例和上榜原因。机构证据不参与 P1 筹码结构完整性和摘要结论, 也不用于推断账户身份或生成任何身份筹码比例。查询继续严格 DB-first; 用户可分别选择“同步结构”“同步机构”或“同步全部”, 其中全部同步固定先更新结构, 再按更新后的本地交易日同步机构证据。机构数据按交易日全量请求, 同一交易日无论包含多少股票都只请求一次。

筹码结构列表直接展示事实日期、最近同步时间、获利筹码、厚浮盈区、薄浮盈区、套牢区和深度低位筹码, 便于区分“数据事实属于哪一天”和“本地缓存何时更新”。每日 18:00 统一盘后批次同步 `cyq_perf` 与 `cyq_chips` 两个结构来源, 不自动请求机构席位数据; 机构证据仍需用户显式点击同步机构或同步全部。工作台同时显示调度注册状态、上次运行结果、下次时间和持久化失败摘要。

FR-227 P1 起, `MorningAuction` 从旧的池子 Tab 和多张表格堆叠, 改为对齐设计稿的早盘战情台。页面结构包含顶部上下文栏、单一战情指挥区、池子统计条、左侧筛选与高密候选表格、右侧 292px 白盒研判面板; 交易日、筛选、刷新、筹码同步、历史回测和股票走势图入口继续复用原有交互。FR-227m 起, 指挥区左侧展示页面名称和当前焦点, 右侧统一承载页面动作与“竞价候选、强意图、涨停确认、同日筹码”四项紧凑指标带, 不再为每项状态建立独立数据卡。候选排序、池子统计、验证清单和风险标签由 `morningAuctionViewModel.ts` 基于现有快照和筹码结果纯前端派生。战情台中间的信号分类、池子统计卡、搜索框、排序下拉和快捷过滤均为本地真实交互, 不应退化为只改变样式的静态按钮。

FR-227 P2 起, 后端将已有竞价快照、题材、筹码、分钟缓存和竞价回测明细聚合为可持久化的结构化 insight。候选强度排序优先使用结构化分数; 右侧默认“研判”视图只展示当前股票摘要、分时承接、三条重点证据、关键风险与待验证项, “证据”视图再展示分项得分、完整验证清单、筹码详情、回测摘要和生成状态。insight 缺失、生成失败或局部证据不足时继续使用 P1 派生模型, 不阻断候选浏览; 降级横幅必须明确说明不可用的是 P2, 当前 P1 白盒研判仍在工作。开发环境可附加后端返回的非敏感诊断详情, 生产环境只展示稳定错误消息。分时证据缺失时保留受阻空态, 不绘制模拟走势。结构化生成只读取已有快照和本地缓存, 不借研判生成触发外部行情请求。用户修改验证状态后通过 IPC 持久化, 后续自动重新生成会按验证项键保留人工确认结果。

FR-227r 起, 早盘题材不再直接取 `conceptNames` 前两项冒充主炒。主进程用上一交易日 `kpl_concept_daily.theme/lu_desc` 作为直接原因事实, 用当前竞价候选的同题材数量、平均竞价涨幅和金额作为共振证据, 普通多源题材成分只作为静态关联；融资融券、沪深股通等基础属性在没有直接原因时降权。快照股票携带可选 `themeAttribution`, 结构化研判通过既有题材验证项 JSON 保存归因快照。表格只展示“主炒/主炒线索 + 共振 + N”, 点击后用 Portal Popover 分组查看全部题材、直接原因、事实日和同方向股票；浮层只允许通过 Esc 或显式关闭按钮退出，外部点击和滚轮不会打断阅读。右侧“这只股今天在炒什么?”明确这是早盘主驱动判断。没有直接原因且不足两只有效候选共振时统一显示“主炒题材待确认”, 不调用AI补写理由。

FR-227s 起, 主进程从已归因的竞价候选反向聚合市场题材, 计算有效候选数、涨幅中位数、竞价金额、接近涨停数量和龙头金额集中度, 再与严格早于竞价日的最近 `eastmoney/verified_flow` 观察交叉验证。名称一致优先匹配, 名称粒度不同时只允许用有限核心股票重合兜底。页面在池子摘要与候选队列之间展示最多三项“今日竞价主线”, 固定标明系统自动判断、资金事实日、覆盖率和双确认状态；点击主线按其股票集合筛选, 再次点击恢复进入前的候选池。右侧个股研判同步展示“昨日资金 × 今日竞价”；该状态只表达盘前证据, 不代表必然延续或交易建议。
新 renderer 读到已完成快照但缺少 `marketThemes` 时, 必须识别为 Electron 主进程尚未加载新契约，展示“重启应用加载主线”恢复动作；不得显示为普通无数据，也不得要求用户重新同步已有竞价、题材或资金事实。

FR-227t 起, “历史回测胜率”升级为公共全高抽屉中的“竞价信号历史表现”。工作台按结论、成熟样本/胜率/平均收益/平均超额/结果缺口、五类池比较、T+1至T+5收益路径和样本/市场环境明细组织信息。胜率与均值只使用成熟收益，待到期与已成熟但缺日线分别披露；读取明细前主进程使用本地 `daily_close_cache` 幂等修复空收益，不联网且不覆盖已有值。7/30/60/90日补齐遵循当前范围；样本行支持双击或Enter打开公共日K与筹码峰抽屉。

FR-227o 起, 早盘页面将异常与缺口分为应用运行时故障、非交易日、快照未就绪和局部证据缺失四类。恢复区分别说明原因、影响和可执行动作, 支持受限应用重启、切换最近交易日、刷新快照、重建结构化研判、同步筹码、打开数据工具、进入走势图和查看历史回测。非交易日返回空快照, 不借上一交易日涨停池生成伪候选; P2 整体失败时明确保留 P1 白盒研判。指挥区统计分别展示去重股票数、候选池记录数、已生成结构化记录、待生成结构化记录和受阻证据项, 不再把不同对象的数字合并为模糊的“研判/缺失”。

FR-227p 起, 恢复区默认使用单行摘要和内联动作, 详细原因按需展开, 并可关闭当前问题。关闭状态按问题键、说明、影响和数量生成签名, 只隐藏当前问题组合; 后续错误内容或统计变化会生成新签名并重新显示。结构化研判重建期间按钮进入等待状态, 成功或失败均展示临时结果提示。兼容筹码摘要查询在主进程中一次选出同交易日最优代码记录, 保持后缀代码优先和 DB-first 边界, 页面重建不因此触发额外外部请求。

FR-228 T1303 起, 早盘集合竞价按当前候选代码批量读取本地兼容型筹码结构摘要, 并以竞价交易日计算 `same_day/history/missing` 日期关系。只有同日且至少包含一个有效筹码指标的摘要参与后端筹码分、前端回退排序、筛选和筹码覆盖统计; 同日空摘要与历史摘要都不能贡献当前竞价日分数。历史摘要仍展示事实日期与旧底部筹码/松动结论, 结论方向使用事实日自身涨跌幅, 不与当前竞价涨跌重新组合。页面打开只查询本地摘要, “同步筹码”仍是用户显式触发的独立联网动作。

FR-228 T1557/T1575起, 早盘竞价、尾盘、涨停、连板、首阴、低吸、个性选股、筹码结构、趋势、产业链节点和回测结果中的股票快捷详情统一使用 `StockKlineChipDrawer`。保持各页面既有点击或双击触发方式，从右侧打开覆盖整个应用的全高模态抽屉，展示30/60/120日日K、均线/BOLL、价格级筹码峰和技术因子；点击K线联动历史筹码。抽屉不依赖点击坐标，使用50%暗色蒙层隔离背景并覆盖Electron标题栏，左边缘支持拖动或键盘调宽，Esc与44px关闭按钮均可退出。

FR-228 T1558 起, 快捷抽屉的筹码峰升级为终端式价格剖面: 最新日期柱体从右向左展开, 顶部展示浮盈筹码、套牢筹码和距主峰, 图中标注累计 15%-85% 核心成本区, 并使用与 K 线一致的中性青色现价线。红/绿只表达相对参考价的浮盈/套牢成本状态, 不表达账户身份或未来方向。点击历史 K 线后进入双侧蝴蝶比较, 左侧为所选历史日、右侧为最新日, 两侧共享价格和占比尺度; Tooltip 同时显示两日占比和百分点变化。快速切换仅做短时柱宽过渡, 减少动态效果设置下直接显示终态。

策略实验室通过 `StrategyLab` 聚合个性选股白盒模板、条件积木分钟模板和新建规则骨架。FR-225 P2/P3 起, 策略实验室拥有独立的 `strategyLab:*` IPC、本地策略模板表、统一 run/match 表和回测联动入口。FR-225j 起, 个性选股和条件积木不再作为中央整页视图嵌入, 而是作为策略来源、执行引擎和证据来源进入统一控制台; 旧的 `personalScreener` 和 `conditionBlocks` 子页签持久化值会自动映射为对应策略上下文。

条件积木页通过顶层 `conditionBlocks` IPC 命名空间读取策略模板、运行本地扫描和查看命中证据。界面采用结果优先布局：主区域展示扫描结果表和筛选控件, 模板 JSON 与单条命中证据收纳到详情弹窗中按需查看；复杂拖拽式图形化编辑器留给后续统一策略模板阶段。

FR-214 起, 条件积木扫描范围支持 `allMarket` 全市场候选来源。该来源从本地 `daily_close_cache` 构建全市场股票池。FR-216 起, 扫描会先用日线做本地预筛, 再按“股票 + 交易日”检查 `stock_minute_cache` 缺口; 缓存命中时绝不触网, 只有日线预筛候选缺失分钟线时才按限量限速补拉。FR-217 起, 条件积木默认进入完整扫描模式：日线预筛候选全部进入分钟覆盖率检查, 缺任一目标交易日分钟线的股票不会被当成已评估样本; 能补齐则参与求值, 不能补齐则进入未评估集合并在摘要和 `log.txt` 中说明原因。快速扫描模式保留补拉上限试跑语义, 但 UI 会明确提示样本可能不完整。FR-218 起, 历史分钟缺口新增数据能力分层：条件积木只调用统一分钟数据入口, 后端按用户层级路由到实际 Provider。免费层默认使用新浪历史 5 分钟近似能力; 付费层优先请求 1 分钟精确能力, 当前云端未配置时可按允许近似策略回落。5 分钟数据写入独立的 `free_minute_cache`, 不写入 `stock_minute_cache`, 后续模板和再次扫描可复用同一 Provider、粒度、股票和交易日的基础数据; 摘要和 `log.txt` 会标注用户层级、粒度、来源和是否近似。

## 主要 props/state/事件流

- `ShortTermStrategy` 通过 Zustand 中的 `shortTermActiveSubTab` 控制当前子页面。FR-222 起, App 壳层二级 Flyout 是唯一可见的短线策略二级入口, `SHORT_TERM_SUB_TABS` 继续作为 Flyout 与路由的单一配置来源。FR-227q 起, 根组件集中管理题材源和同步状态, 早盘、打板、连板龙头、龙头首阴和低吸雷达通过 `dataTools` 插槽在各自标题操作区呈现“题材数据 · 来源名称”入口; 只消费日线、分钟线和条件求值的策略实验室不再显示无关题材入口。FR-225 起, `strategyLab` 是个性选股和条件积木的主入口; 历史值 `personalScreener` 和 `conditionBlocks` 会在页面内映射到 `StrategyLab.initialView`。
- `ShortTermDataToolsDrawer` 复用全窗口 `RightDrawer`, 以独立滚动正文展示题材用途、来源分段选择、本地题材状态、最近同步时间和同步进度, 并将题材维护与盘后基础数据同步分区。THS 是同花顺题材成分来源, 用于题材标签、共振验证和候选筛选, 不是行情源。同步开始后抽屉保持打开并就地反馈, 不得恢复为向视口外展开的底部菜单。
- `StrategyLab` 维护 `activeView/selectedStrategyId/runs/matches/selectedMatchId`, 中央主区域固定展示策略标题、运行模式、KPI、策略管线、当前策略摘要、配置区和统一命中表; 左侧模板库负责真实策略选择和复制/启停/删除, 右侧运行计划和命中研判展示最近 run、回测状态和选中 match 的证据摘要。
- `strategyLab:runStrategy` 只编排已有个性选股与条件积木执行能力, 不新增行情请求、不调用 AI 自动生成规则, 不改变原策略引擎口径。草稿策略会被后端拒绝运行, 需要后续编辑为 ready 策略后才能进入统一运行。
- `MorningAuction` 展示早盘竞价各池候选股, 3日/5日涨跌由后端 `mergePriceHistory` 基于 `daily_close_cache` 和 Tushare daily 补齐。
- `MorningAuction` 通过 `buildMorningAuctionWorkbench` 将三一池、弱转强池、板态池和全市场池合并为统一候选队列; 中间信号分类切换当前候选类型, 池子统计卡切换大池, 搜索/排序/快捷过滤进一步收窄队列。队列使用 sticky 表头和高密列展示竞价开盘、竞价涨幅、现价、现涨幅、现价成交额、3日/5日涨跌、题材、筹码结论、竞价金额和竞价换手率, 选中项驱动右侧研判面板, 双击候选打开近期日 K 与筹码峰抽屉, 抽屉内“打开完整走势”再进入股票走势图。历史回测、同步筹码和数据工具属于指挥区全局动作, 不在筛选区重复放置; 四项核心状态在同一表面内使用轻量分隔指标带展示。候选队列表格必须在自身区域内滚动承载长列表。
- `MorningAuction` 读取快照中的可选 `marketThemes`, 最多展示前三项竞价主线。第一次点击时保存当前候选池并切换到全候选后按主线股票代码过滤, 再次点击同一主线恢复原候选池; 手动切换候选池会退出主线筛选。市场主线筛选、搜索、交易所、题材和状态过滤可以叠加, 不修改原始快照。
- `MorningAuction` 读取快照后调用 `shortTerm:morningAuction:generateInsights`, 以 `tsCode + poolKey` 索引结构化 insight。强度排序优先使用持久化分数, 无 insight 时回退 P1 `rankScore`; 选中候选后右侧面板按同一索引读取结构化证据。
- `MorningAuction` 保存 `tradeDateStatus` 并通过 `buildMorningAuctionRecoveryState` 聚合快照错误、结构化错误、日期状态、统计和 insight 证据缺口。恢复动作复用现有页面行为; “打开题材数据”通过 `onOpenDataTools` 打开根组件已有抽屉, 不复制同步入口; “重新启动应用”调用无参数 `app:relaunch`, renderer 不能传入路径或命令。
- `MorningAuction` 使用当前恢复问题签名保存关闭状态。问题签名变化时恢复区自动重新显示; 手动重建通过 `insightLoading` 锁定重复操作, 并通过 `insightFeedback` 展示五秒成功或失败反馈。
- `MorningAuction` 同时调用 `chipStructure:getSummaries({ tsCodes, referenceTradeDate })` 批量读取候选摘要, 将结构指标、旧兼容字段、事实日期和日期关系放入同一 `chipDataMap`。`morningAuctionViewModel.ts` 只给同日有效摘要增加回退排序分, “同日筹码”筛选和覆盖统计使用同一判断。快照、筹码摘要和 insight 各自使用请求序号与目标交易日校验, 日期切换时旧响应失效且旧日期状态立即清空。
- 验证项状态通过 `shortTerm:morningAuction:updateVerification` 更新。页面只局部替换当前候选 insight, 不重新加载整张快照; 可选状态为待确认、已核验、受阻和不适用。
- `shortTerm:morningAuction:refresh` 完成事实快照刷新后非阻塞重建 insight; 证据视图中的“重建当前研判”传入当前交易日和选中股票 `tsCode`, 返回结果只合并当前股票对应的 `tsCode + poolKey`, 不清空其他候选 insight, 也不重算整页完成统计。没有快照时返回明确错误, 不触发外部请求。
- 早盘集合竞价的“同步筹码”会把当前三一池、全市场池、弱转强池和板态池的去重候选写入独立的 `morningAuction` 来源, 后端只计算该来源股池; 若 Tushare 未启用或已有任务运行, 页面会在顶部错误横幅展示原因。
- 百股批量同步按股票各发起一次 `cyq_chips` 历史请求, 再仅保存最近10个目标交易日, 不得按股票和交易日展开为上千次请求。已命中缓存的股票直接计入进度; 完成反馈明确区分成功数与上游无数据数, 行状态使用“未同步 / 同步中 / 同步无数据”, 不再把已尝试失败统一显示成“待补”。
- `ChipMonitor` 维护 `stocks/statusCounts/selectedCode/detail/sourceFilter/statusFilter/search/chipMode/running/progress/drawerStock` 等状态。左侧单击股票驱动右侧事实详情查询，双击使用公共 `StockKlineChipDrawer` 打开近期日K与筹码峰；搜索使用延迟值减少连续 IPC 请求。
- 筹码结构列表和详情分别由 `chipStructure:listStocks`、`chipStructure:getStockDetail` 提供, 两者只读取本地缓存。显式同步由 `chipStructure:refresh` 启动, `scope` 可选 `structure/institution/all`; 进度事件同时携带当前 `scope`、`stage` 和 `noRecord`, 完成后通过 `chipStructure:done` 刷新列表、当前详情和兼容低位指标。
- 筹码结构列表请求按当前筛选参数做重入保护, 相同请求未完成时不会重复提交; 切换筛选或股票时使用请求序号忽略过期响应。同步按钮在 IPC 返回前立即锁定, 后端返回 `JOB_RUNNING` 时恢复既有任务进度, 不启动第二轮同步。
- `ChipMonitor` 支持“导入持仓”和“导入自选”两条入口。导入仍复用现有 `shortTerm:chipMonitor:syncPortfolio/syncWatchlist` 维护股池, 用户确认后只触发结构同步, 不隐式启动机构数据请求。
- 机构证据状态严格区分 `available/no_record/not_synced/failed`。`no_record` 仅表示该交易日的上游请求成功但没有可用席位记录, 不表示没有机构交易; `not_synced` 表示该日期尚未同步; `failed` 表示最近一次日期同步失败。
- 机构同步先批量读取全部目标股票的最新事实日期, 再按日期分组请求 `top_inst`; 无筹码事实的股票只通过一次批量日线查询补目标日期, 不逐股装配完整详情。
- 相对低位和绝对低位模式只影响兼容区的底部占比与 1/3/5 日松动口径; FR-228 的成本分位、获利/套牢结构和一致性事实不随该模式改变。
- `ConditionBlocks` 维护 `templates/selectedId/templateJson/matches/selectedEvidence/running/scanStep/lastSummary/toast` 等状态，调用 `conditionBlocks:listTemplates/getTemplate/runScan/listMatches/getMatchEvidence` 完成本地扫描闭环；结果表支持按股票代码或名称搜索、最低得分和数据状态筛选。
- 条件积木模板 JSON 通过顶部“模板详情”按钮打开弹窗查看, 不在主区域常驻展示；命中证据通过结果表每行“证据”按钮打开弹窗查看, 避免遮挡结果列表。
- 条件积木扫描通过 `conditionBlocks:progress` 推送真实进度, 按“准备模板与股池 → 执行日线预筛 → 检查分钟缓存 → 检查并限速补拉分钟线 → 执行分钟条件 → 写入扫描结果 → 完成”展示阶段；补拉阶段会展示当前/总数、成功、失败、空数据和上限跳过数量。
- 条件积木扫描中可点击“终止扫描”, 前端调用 `conditionBlocks:cancelScan`; 后端停止未开始的补拉和评估, 已写入的免费 5 分钟基础缓存保留, 下次运行继续复用。
- 开发环境会读取配置中心“用户层级”页签保存的本地模拟值, 并通过 `conditionBlocks:runScan.userTier` 传给后端; 生产环境不展示该配置入口, 默认按免费层级路由。
- 条件积木扫描完成摘要区分本地日线覆盖、日线候选、分钟完整、已评估、未评估和命中数量; `allMarket` 表示候选来源来自全市场日线底座, 不表示全市场分钟线都已补齐或都参与分钟条件求值。
- 条件积木扫描摘要会展示分钟数据能力, 包括数据来源、粒度、精确评估股票数和近似评估股票数。使用 5 分钟近似时, UI 会以提示块标明结论不是 1 分钟精确扫描。
- 条件积木运行扫描时使用页面上的扫描参数覆盖模板默认值, 包括扫描模式、开始日期、结束日期、日线预筛上限和分钟补拉上限; 覆盖后的日期、上限与扫描模式会参与后端参数哈希, 避免不同扫描区间或完整/快速模式误复用缓存。
- 条件积木扫描参数收纳在“扫描配置”弹窗中, 顶部只展示当前配置摘要; 扫描完成后默认展示“本地日线覆盖 → 日线候选 → 分钟完整 → 已评估 → 命中”的漏斗摘要, 详细补拉指标通过“展开详情”查看。
- 导入入口启动计算时会传递对应来源；持仓导入只计算 `portfolio` 来源，自选股导入只计算 `watchlist` 来源，避免误扫整个监控股池。
- 股票名称展示优先使用监控股池名称，其次使用结果查询从 `stock_info` 兜底带回的名称，避免旧股池空名称导致界面只显示代码。
- 个性选股页新增 AI 逐票解读入口，单只解读通过 `shortTerm:screener:getInsight` 读取本地证据包后生成四段式说明；批量入口处理用户勾选的当前可见股票，通过 `shortTerm:screener:insightProgress` 展示进度，单次最多 10 只。
- 个性选股 AI 解读只解释本地筛选证据，不改变 L1 圈选规则、L2 排序和任何阈值；若 AI 输出触发交易指令边界检查，前端展示后端生成的安全摘要。

## 特殊逻辑备忘

- `chip_monitor_results.ts_code` 可能是 `600000.SH`，`chip_monitor_stocks.ts_code` 可能是 `600000`，前后端查询和展示都需要按 6 位代码归一化匹配。
- 筹码结构名称不依赖计算结果写库，后端查询会从监控股池和 `stock_info` 对空名称做兜底。
- 筹码结构列表由监控股池驱动, 没有结构快照的股票仍返回 `blocked` 行; 顶部完整、部分、缺失、一致性和过期统计使用未被当前状态筛选压缩的股池口径。
- 列表摘要使用批量轻量事实路径, 不装配机构席位明细、完整价格峰或兼容详情。日线最新交易日按一次请求读取并由 `trade_date` 索引支撑, 列表查询成本主要受当前股池和最多 30 个筹码交易日窗口约束, 不随全市场日线总行数线性增长。
- 同一股票多来源时，后端按 `portfolio > morningAuction > screener > watchlist` 选择展示来源，避免结果行被 JOIN 放大。
- 顶部“刷新本地”只重新查询缓存, 不访问外部数据源; “同步结构”“同步机构”和“同步全部”是显式联网入口。导入持仓和自选后的自动动作仍限定为结构同步。
- 机构席位成功空响应必须写入日期覆盖事实并展示为 `no_record`; 同步失败只记录失败尝试, 不删除旧的成功明细或成功覆盖事实。
- 同一席位经济记录可能同时出现在买入榜和卖出榜, 聚合前按忽略 `side` 的经济键折叠, 避免金额与席位数重复计算。
- 机构证据面板始终展示数据范围局限: `top_inst` 只覆盖公开上榜席位记录, 不能代表全部机构活动, 也不能与价格级筹码分布建立账户归属关系。
- `cyq_perf`、`cyq_chips` 和同日收盘价必须按同一交易日组装。日期错配返回 `DATE_MISMATCH`, 不使用旧成本分布配新价格制造伪结论。
- 官方获利比例与价格级重算值分别保留, 差异超过阈值时标记一致性告警, 不自动选择其中一个覆盖另一个。
- 结构变化按有效筹码交易日计算, 不是自然日差。历史不足时返回空值和 `INSUFFICIENT_HISTORY`, 不用零值代替缺失。
- 1/3/5 日松动为空时可能是有效历史筹码日不足或历史底部占比分母过小，前端通过松动列 tooltip 展示后端返回的缺失原因。
- 早盘集合竞价的 3日/5日涨跌在刷新路径中等待后端补齐后再返回；日线补拉按小批量调用 Tushare daily, 避免全市场异动池股票较多时单次 `ts_code` 列表过长导致整列显示横线。
- 早盘集合竞价 P2 的优先级分是固定规则白盒评分, 只表达观察优先级, 不代表收益概率、胜率或交易建议。分数限制在 0～100, 缺失证据使用 `blocked`、`null` 或 `partial` 表达, 不以默认高分伪造完整结论。
- `morningAuctionViewModel.ts` 继续作为结构化 insight 缺失或失败时的 P1 回退层, 不应因 P2 接入而删除。自动重建 insight 仅在 schema 一致且新验证项仍可验证时保留 `checkedByUser` 的状态、原因和更新时间; schema 变化或验证项转为 `blocked` 时不得继承旧人工确认。
- `morningAuctionRecoveryModel.ts` 只负责把已知状态转换为用户可理解的问题和恢复动作, 不改变候选、评分或证据计算。应用故障不得伪装成数据缺失, 非交易日不得显示为加载失败, 局部证据受阻也不得升级为 P2 整体失败。
- 兼容筹码摘要仓库的日线匹配必须在真实 SQLite 中执行回归。代码优先级为请求结果的精确 `ts_code`、任一带交易所后缀代码、最后六位代码, 三个日线字段必须来自同一条记录。
- 竞价 insight schema v2 将可选 `chipEvidence` 放入现有验证项 JSON, 旧记录无需数据库迁移; schema 不匹配时重新生成。历史筹码证据的贡献分固定为 0, 筹码一致性验证保持受阻。
- 早盘集合竞价页面内不再渲染自己的二级 Tab; 入口切换由 App 壳层二级 Flyout 和短线策略一级状态负责, 避免页面内重复导航。页面视觉必须继续贴近 `targetPic/morning-auction-redesign-demo.html` 的 context bar、page head、pool strip、table panel 和 insight panel 分区。
- 竞价主线资金日期必须满足 `flowTradeDate < snapshot.tradeDate`; 页面不得使用全局最新板块资金解释历史竞价。缺少昨日已核验资金时保留“仅竞价转强”或“证据不足”, 不触发额外联网补拉。
- 早盘指挥区在宽窗口使用左右布局, 窄窗口允许命令区和指标带整体落到标题下方; 操作文字、指标标签和数值不得逐字换行。右侧“研判 / 证据”切换组使用不可收缩的横向分段控件, 两个按钮保持单行和稳定最小宽度。
- 短线策略的提示块和形态卡片避免使用粗侧边色条, 状态强调改用细边框、淡色背景和文字色区分, 以降低模板化视觉痕迹。
- 短线策略二级页签不使用 emoji 作为结构性图标; 新增子页签时需要同步更新 `SHORT_TERM_SUB_TABS` 和 App 壳层二级 Flyout 配置。
- 筹码监控表格 tooltip 箭头使用旋转方块, 避免与真实卡片侧边强调条混淆。
- 个性选股 AI 解读缓存按 `tradeDate + tsCode + evidenceHash` 命中；证据变化会自然生成新缓存，避免旧解读覆盖新的筛选上下文。
- 条件积木命中结果会保存完整条件证据 JSON，扫描摘要写入 run 的 `summary_json`，方便定位 0 命中是股池为空、日线预筛过窄、分钟线未覆盖、候选未评估还是规则阈值过严。
- `allMarket` 只代表“从日线底座取得全市场候选”, 不代表全市场分钟线已经补齐；完整扫描会尝试补齐日线候选的全部目标分钟缺口, 快速扫描才使用默认最多 80 个“股票-交易日”缺口的试跑上限。
- 分时补拉必须严格 DB-first: `stock_minute_cache` 已有目标股票目标交易日数据时, 扫描器不得再调用 Tushare 或东财分钟接口。
- 条件积木扫描会在项目根目录写入 `log.txt`, 内容为候选级状态数组, 包含股票代码、股票名称、需要分钟交易日数、已有分钟交易日数、补拉成功交易日数、缺失交易日、是否参与评估和未评估原因, 便于人工核查扫描母集。
- `log.txt` 的候选状态还会记录数据粒度、数据来源和是否近似; 若历史缺口由新浪 5 分钟兜底补齐, 该候选会被明确标记为近似评估。
- 条件积木后端参数哈希包含扫描模式、分钟数据用户层级、Provider、粒度和是否近似, 避免免费近似扫描与付费精确扫描互相命中缓存。
