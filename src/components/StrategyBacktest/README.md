# 策略评估与历史回测组件

## 模块功能

`StrategyBacktestPanel` 是「短线策略 > 策略评估」的页签容器。FR-242 起默认展示 `StrategyEffectivenessWorkbench`, 用真实策略信号直接比较次日、第2/3/5个交易日表现；原资金参数回测改名为 `LegacyStrategyBacktestPanel`, 保留在“历史报告”次级页签。

效果评估不要求用户配置初始资金、仓位、买入数量或真实持仓。它回答策略选出的股票后来表现如何、不同策略谁更有效，以及结果是否受到样本量、单日信号爆量或策略重合影响。

## 实现思路

- `StrategyEffectivenessWorkbench` 通过只读 `strategyBacktest.evaluateSignals` 读取策略目录、排名、四周期路径、稳定性、有限明细和重合关系；评估不会创建历史 run。
- 效果评估首次进入默认查询北京时间今天向前偏移30个自然日的信号范围；用户仍可使用日期选择器扩大或缩小区间，切换到已有数据范围时以用户确认后的区间为准。
- 单策略与多策略使用同一聚合模型；只有一套策略时仍展示自身样本、收益、胜率、分位数和收益路径，不因没有重合关系而进入空白状态。
- 早盘竞价复用既有9:25竞价撮合价和已计算的四周期/基准收益，默认排除一字板不可执行样本；“板票竞价双第一”在读取层聚合四个板票池并按策略、股票、信号日去重。
- 策略实验室只读取每个策略最近一次完成运行的真实命中，以信号后的下一交易日开盘为观察起点，并从本地 `daily_close_cache` 计算四周期方向调整收益和基准超额。
- 排名同时展示按信号等权与按信号日等权；后者降低单日大量信号对结论的支配。少于5条有效样本的策略降级排序，空值不转成0。
- 收益路径和稳定性使用 Recharts 且关闭图表动画，排名、信号明细和重合表提供同等数据表达；暗色与系统减少动态效果均受支持。
- 效果评估默认挂载；历史报告首次访问后保持挂载，后续通过显隐切换保留两边状态，避免切换页签后丢失筛选或当前报告。

- 通过 `window.api.strategyBacktest` 调用主进程 IPC。
- 回测内核复用主进程的 `runStrategyBacktest`, 组件只负责参数收集和结果展示。
- 运行参数包括信号源、策略键、日期范围、入场规则、持有期、止盈止损、费用和强制重算。
- 信号源支持 `shortTerm`、`trendAlerts`、`decisionSignals`, 切换时自动给出对应策略键示例。
- 缓存键同时绑定运行参数、回测引擎版本、输入事实指纹和FR-246相关数据质量指纹。事实指纹覆盖归一化信号、参与撮合的目标行情以及基准实际使用行情；日线、交易日历或核心基准质量边界变化也会重新计算。
- 勾选强制重算时重新生成 run; 重算失败不得删除同一事实下最后一次成功报告和交易明细。
- 报告中的强度比较来自主进程统计结果；少于10笔、只有一个评分值或不足两档时不分层，有差异时最多形成五个从高到低的档位且相同评分不拆组。UI不重新计算收益统计，但会使用既有交易明细为样本数提供名称、代码和信号日Tooltip。
- V4 报告按出场日聚合有效交易，同日净收益等权平均，再按实现日顺序复合生成权益曲线；页面展示累计实现收益和基于历史权益峰值的实现净值回撤。
- V4 报告固化五道可信度门、三档结论、前后半区间切片和相关质量指纹；效果评估只读生成同口径快照。主层不暴露原因代码或完整哈希。
- 回测运行时监听 `strategyBacktest:progress`, 展示读取信号、加载日线、撮合交易、计算基准和写入结果等阶段进度。
- 第214阶段起, 信号和策略复用产业研究可搜索组合框, 开始与结束日期复用同一 `ResearchDatePicker`; 开始日期受结束日期约束, 结束日期受开始日期和北京时间今天约束。
- 参数区按信号与区间、交易规则与费用分组。入场方式使用分段控制, 强制重算使用开关, “运行回测”是唯一主操作。
- 页面挂载或切换信号/策略后自动读取最近一次成功的本地报告和交易明细, 不自动运行回测。列表与报告请求使用序号隔离过期响应。
- V4 `equityCurve` 由 `BacktestEquityChart` 直接可视化为累计实现收益和当前回撤；前端不重新计算撮合、可信度或报告统计。
- 历史列表和报告主层使用本地化策略名; 引擎版本与事实指纹收纳到默认折叠的技术审计区。

## 主要状态和事件流

- `signalSource/strategyKey/dateStart/dateEnd/plan/force`: 表单参数。
- `report`: 当前报告指标。
- `runs`: 当前信号源和策略键下的历史 run 列表。
- `trades`: 当前 run 的交易明细。
- `progress`: 当前回测阶段进度, 由主进程事件推送。
- 点击“运行回测”后调用 `strategyBacktest.run`, 成功后并行刷新历史 run 和交易明细。
- 点击历史 run 后调用 `strategyBacktest.getReport` 与 `strategyBacktest.getTrades` 回填界面。
- 历史列表展示运行状态和可信状态; 失败 run 不允许打开报告或交易明细。

## 特殊逻辑备忘

- `strategyBacktest.evaluateSignals` 与页面挂载严格只读本地竞价明细、策略实验室最近完成运行和日线缓存，不联网、不调用AI、不改写旧历史报告。
- 当前区间没有信号时，页面展示所选策略本地可用日期范围；可切换到共同可用区间，或由用户明确点击“补齐当前区间”复用既有 `shortTerm.backtestRun`。补齐过程显示进度，完成后按原筛选自动重新评估。
- 策略实验室尚未运行的策略仍出现在目录中并说明不可评估，不回退到其他信号表伪装为当前策略结果。
- 明细响应最多返回1000条以保护IPC，但排名、覆盖、路径和重合关系使用裁剪前完整集合计算。
- 旧preload没有 `evaluateSignals` 时，效果评估明确提示完全重启应用；“历史报告”仍可进入。

- 面板只消费主进程返回的本地回测结果, 不触发 Tushare、东方财富或 AI 调用。
- `trendAlerts` 信号源强度固定为 1.0; `decisionSignals` 的强度由后端按 score/confidence/priority 归一。
- 基准收益由后端基于本地 `daily_close_cache` 计算; 数据不足时展示 `benchmarkNote`。
- 交易明细主列展示股票名称, 代码作为辅助小字; 名称来自信号 `meta.stockName` 或本地 `stock_info` 兜底。
- 剔除率高于 20% 时展示样本风险提示, 提醒用户关注本地日线底座不足或停牌造成的偏差。
- 零信号或零有效成交返回 `blocked`, 不可用统计字段为 `null`, 页面显示“不可统计”, 不伪装为 0%。
- 权益曲线只在交易出场日确认已实现收益，不表示逐日盯市净值；重叠持仓不模拟资金占用和仓位分配，因此V4的成交可执行性与稳健性门第一批最高为 `degraded`。
- V1-V3旧报告继续可读，但统一标记 `LEGACY_REPORT`，不伪造V4可信度，也不参与V4缓存命中；旧回撤口径不映射为实现净值回撤。
- 已有 `strategyBacktest:progress` 用于展示长任务阶段, 本阶段不新增 IPC 通道。
- 第216阶段起，`shortTerm.*` 与 `strategyLab.*` 分别严格匹配自身策略前缀；信号来源本地化为“策略信号库”，策略项明确区分短线模块与策略实验室。该定义覆盖第215阶段把 `shortTerm.*` 扩大为全表的临时兼容语义。
- 第218阶段起，历史报告可直接选择板票竞价双第一、首板、二板及以上、炸板封回、断板和竞价全市场异动。`stk_auction_backtest_detail` 只提供信号日、股票和来源池；表内既有买入价与T+N收益不会代替用户当前配置，入场、持有期、退出、费用和权益仍由统一引擎基于本地日线重新撮合。
- `shortTerm.*` 合并真实 `shortTerm.%` 与竞价信号并按同股同日去重，`strategyLab.*` 继续严格隔离。引擎 `3.1.0` 使新运行不命中旧错误缓存；旧历史报告保持不可变，必须重新运行才会生成修复后的新报告。
- 第219阶段起，全部竞价信号强度同为 `1.00` 时不再展示任意 `#1-#10`，而是说明该来源没有可比较评分；旧同区间报告同样在渲染层纠正。真实分档使用最高/较高/中等/较低/最低强度，样本数可悬停或聚焦查看前20笔股票名称、代码和信号日，完整名单仍以下方交易明细为准。新运行使用引擎 `3.2.0`。
- 单实现日报告在渲染层增加不持久化的0%起点，使唯一真实权益点形成可见线段，并直接说明实现日与同日出场笔数；回撤向零轴下方绘制，最大回撤摘要不增加正号。多个实现日不增加绘图点，零权益点继续使用空态。
- `NO_SIGNALS` 与 `NO_VALID_TRADES` 在报告主层分别说明“日期内无匹配信号”和“已有信号但T+1/持有期/收盘日线尚不足”，不再只显示泛化的基准缺口。
- 历史项包含独立删除命令。`BacktestDeleteDialog` 通过Portal提供项目内模态确认、取消优先焦点、Esc、遮罩关闭、Tab约束、背景锁定、明暗主题与减少动态效果，不使用原生 `window.confirm`。确认后通过 `strategyBacktest.deleteRun` 在主进程事务删除run与交易明细；删除选中项会自动打开下一条成功记录，无剩余记录时清理报告和明细进入空态。
- 渲染层调用删除前检查 `deleteRun` 是否实际存在；旧preload仍在运行时，确认层切换为“需要重启应用”并提供显式重启动作，本次不删除记录，也不再向用户暴露 `api.deleteRun is not a function`。
- 第231阶段起，效果评估和历史报告共用 `BacktestCredibilityBand`。五道门依次披露数据底座、时间完整性、成交可执行性、样本充分性和稳健性验证；0有效样本、关键底座阻断或时间顺序违规时结论不可用，样本不足时仅作探索参考，至少两套策略且核心门可用时才允许同口径比较。
- 样本充分性第一批门槛为30笔有效样本、10个有效信号日和不高于20%的缺失/剔除率；稳健性先提供按信号日期划分的前后半区间收益与胜率，不将其冒充滚动窗口或样本外验证。
